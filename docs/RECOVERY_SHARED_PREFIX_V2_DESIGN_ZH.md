# 恢复开发 v2：共享前缀设计（尚未批准执行）

日期：2026-11-08。状态：设计，未预留新 seed、未冻结实施清单、未启动采集。v1 记录和源代码保持不变，所有 v1 样本训练准入仍为 false。

## 已有证据与尚未确定的原因

v1 的八场开发回合已结束，四个 seed 没有一个通过完整技术配对。100119 的干预前 47 个动作全部不同；100122 的 46 个动作中 45 个不同。两组均从第一个动作开始出现差异，先于开爪干预。三个未知终态是右臂当前状态路径规划异常，不得改写成任务失败或移出分母。

本机只读源码表明：`RoboTwin/envs/robot/robot.py:set_planner` 构造 CuRobo 规划器；`planner.py:plan_path` 用当前关节位置和目标位姿调用 `motion_gen.plan_single`，起始关节位置取五位小数；MotionGen 配置默认 IK/graph seed 为 1531，并提供独立的 reset_seed 接口。任务初始化设置 NumPy、Torch seed，但 Python random.seed 行被注释。

这些是代码事实，不是根因证明。相同初始 RGB 和关节向量不代表完整仿真状态一致；规划器内部状态、GPU 数值过程、目标位姿或其他随机源仍可能参与差异。不能仅恢复 random.seed 一行就宣称已修复，也不能放宽原有精确动作审计来使 v1 通过。

## 新配对单位

每个新开发 seed 包括一个公共前缀生成回合，以及两个独立重置后的执行回合。公共前缀只生成一次，截止于 lift 完成、首个 place 动作执行之前。生成回合不计作对照成功样本，不得根据最终成功选择其轨迹，也不进行失败后的 seed 替换。

保存前缀的完整 14 维命令、阶段、动作索引、物理时钟、资产与代码 SHA、初始状态及边界状态。生成完成后立即封存 SHA；对照与扰动回合读取同一份封存前缀，并使用原始 take_action 接口执行。不得为任一条件重新规划前缀。

前缀生成失败时，该 seed 两个条件都标记为技术未完成，保留错误及既定分母；不得另取成功前缀。

## 配对审计与分支行为

两条件逐动作的命令和前后物理时钟必须精确相等。初始 RGB、关节状态、物体位姿/速度、机器人关节速度，以及干预边界的对应状态均须记录；状态比较字段、精度和容差必须在执行前冻结，不能看到结果再调整。旧版仅检查初始 RGB/关节位置不足以证明边界状态一致。

任何前缀或边界核验失败立即标记技术不可比，保留日志，不继续将该对用于扰动效果估计。公共命令相同仍可能因仿真状态差异产生不同结果，重放本身不构成通过证明。

边界通过后，对照组从当前状态重新规划 place；扰动组先按当前测量状态生成一次左爪打开动作，再从当前场景规划 grasp/lift/place。干预动作单独标为 external_intervention，不作为专家标签。两组保留官方成功判据、动作/物理步/墙钟上限；不得使用旧场景的放置轨迹恢复。

## 实施与验证顺序

1. 新增独立 v2 前缀文件契约、哈希验证器与重放执行器；不修改 v1 已冻结模块。前缀读取必须拒绝 seed/资产/控制器不匹配、非有限命令、阶段倒退、缺失动作及文件改写。
2. CPU 测试覆盖被篡改前缀、缺失动作、时钟漂移、边界状态不符、干预标签隔离，以及失败不能获得训练准入。测试不能仅验证理想路径。
3. 冻结状态测量契约、比较阈值、独立新 seed 清单、顺序和技术门槛后，进行有界本机开发实验。使用自有 GPU 租约；不启动或加载 Strata。
4. 每次生成/重放均记录输入与输出哈希，按 seed 输出同屏前缀与边界图、轨迹差异图、官方终态和失败原因。技术配对与恢复成功分开报告。
5. 只有开发门通过后才另立规模化采集/训练协议。训练目标窗口不能跨越干预或失败段；源数据仍必须通过同源触觉、真实物理时钟、HDF5 和 completion 审计。

## 与研究结论的关系

M8 的固定数据时长对照已完成 384 场，未支持增加训练步数即可带来独有触觉收益。v2 解决恢复数据的配对可信度，不证明学习策略获益。正式学习实验仍需在同一数据集上比较视觉、错配触觉、真实触觉及受控反馈条件，使用独立闭环 seed，并保留零收益或负收益结果。

本设计尚不能直接交给 GPU 自动队列。实施、CPU 验证、状态契约和 seed 冻结是剩余前置项。
