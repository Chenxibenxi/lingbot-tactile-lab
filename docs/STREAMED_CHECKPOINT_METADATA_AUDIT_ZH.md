# 原154800完整检查点：逐分片路径的**仅头部**预检

原VLA服务端FP32权重一次合并六分片的[主存门禁](<REAL_VLA_MEMORY_PREFLIGHT_ZH.md>)已因RAM不足而拒绝。为判断是否值得设计严格的**逐分片**加载器，[CPU只读审计代码](<../src/stream_shard_metadata.py>)仅打开原外部检查点六个safetensors的**头部和index**，绝不取数值张量、不实例化LingBotV2、不开GPU：

- `model.safetensors.index.json` SHA256 `62dbe509bd476ff354e6a9bea5476bfe451471a5e1160d24abb594a35fe2ec40`（也与此前视觉自回放登记的原检查点索引SHA一致）；映射共**1,624个唯一键**，六分片实际键集合逐片和index完全一致，都是FP32；按各张量形状×4B计算的总值字节数恰等index声明的 **24,905,544,412B**。六分片文件加头部略多，总约23.2GiB。
- 最大单分片文件**4,898,303,408B（约4.56GiB）**；只考虑这一分片和2GiB保守余量，下界 **7,045,787,056B（约6.56GiB）**，2026-11-02凌晨本机`MemAvailable≈12,522,913,792B`，仅此**逐片主存下界**通过。与一次性合并全部权重所需余量不等价。

**这尚不是流式装载器、不是严格模型state_dict键／形状匹配，更不是实际GPU峰值、旧检查点已加载或触觉模型训练。** 下一道门：在隔离生成的真实V2类上先采用meta-device实例验证**所有模型键集合及形状和1,624键完全一致**，不复制原权重，确保构造器不意外占GPU/RAM；失败即停。之后才考虑显式按一个分片复制到BF16模型，并防止部分复制/`strict=False`掩盖缺键、记录原分片SHA与模型device/参数总量；任何真实GPU工作需独立lease、不会越过用户北京时间2026-11-02 12:00的Strata恢复。现有真实训练数据和归一化仍未获正式批准，原H50物理动作门也未过，**不能因为头部预检通过就开训练**。
