# 接触辨识与纠错数据契约草案

状态：待开发验证，不批准训练，不占用独立确认seed。对应现有12回合动作/旁路审计，首先处理空夹和保持，滑移后续扩展。

每条记录必须标记episode、唯一物理步和采集发生在动作之前/之后。策略观测包含实际可测RGB、本体与因果触觉窗口及coverage/age/valid；不能把驱动目标当实际关节位置。记录命令、实际执行区间与关节反馈以区分策略和控制误差。

独立label-only流记录物体位姿/速度、夹爪位姿/速度、物体相对夹爪运动、物体与支撑面的接触、手指与目标物体的接触关联、环境成功判据。隐含摩擦/质量、对象标识、干预标记与世界接触几何仅供生成或评分，禁止拼入策略输入。滑移必须基于相对运动证据及明确坐标系；空夹必须结合闭合/探测动作与目标接触和运动结果，不能简单定义为某帧无接触。

事件时段和阈值只能在开发/训练数据确定，独立评测保持冻结。未来持续保持/滑落结果可以是当前预测的监督标签，但标签窗口不允许进入当前输入。外部干预不是专家动作；动作目标在干预边界截断，未知尾段显式掩码。

开发实验先验证两个动作分支（继续抬升、退回重抓）的可执行性及后果差异，并报告失败。场景配对保持初始外观和控制预算一致；不承诺视觉在接触后仍不可区分，应实测视觉+本体基线。只有同源完成审计、标签有效性与分支效果通过，才冻结独立多seed采集。策略自轨迹和固定脚本动作都不因成功自动成为纠错专家标签。

## 终态与分支标签约束（2026-11-10开发证据）

mu0_continue单seed开发中，完整双瓶任务失败，但右瓶功能点终态满足原任务右瓶几何子判据。因此禁止用摩擦组别、完整双瓶success或瓶体原点高度直接生成右臂“必须重抓”标签。必须分别保存对象功能点、任务子判据、完整任务判据、持续保持及支撑/非指尖接触证据。功能点按资产scale和局部functional_matrix变换到世界坐标，关联资产SHA。

每个分支的结果需保留动作成本和终止原因。若两个分支都可完成，不能把重抓指定为唯一正确动作；若两个都失败，也不能任选一个作为专家。开发阶段先验证分支后果及可靠性，再冻结选优规则和容许的等价动作。当前mu0_continue只是终点几何合格，稳定保持和干净接触尚未通过，training_approval仍为false。
