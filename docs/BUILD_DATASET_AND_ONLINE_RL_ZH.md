# 自建触觉训练数据集与在线 RL：当前阶段说明

## 现在可用什么、还不能做什么

原视觉 LingBot-VLA 检查点可作**冻结基座/视觉-only对照**；历史视觉 HDF5 没有真实物理拍照时间和同回合触觉，不能事后把另一回合的接触值拼上去训练触觉。LXC 双3090旧试片只验证工具，不进新仓库的中继机数据集。

本机中继机单张RTX3090原先独立采两任务各5条规则专家成功回合：`lift_pot` 518 对、`pick_diverse_bottles` 594 对通过因果时间窗筛选，后一任务321对（54.0%）已观察到接触，前一任务123对（23.7%）。后来固定两种子一次性补采了双瓶成功专家2条、另有249个合格对；旧候选v1切分**仍冻结在双瓶5种子594对**，另立候选v2只将新两seed加进训练折，保持旧验证／测试seed不变，形成5训练seed／590对＋原验证126、测试127对；两种版本都**没有训练批准**。提锅旧切分仍是3个实际种子训练、1个验证、1个测试；两条人为开爪失败诊断和视觉策略自回放**不是成功专家下一动作标签**。所有条目为 candidate，`datasets/provenance_v1.json:approved_paired_episodes=[]`、norm `training_approval=false`，所以**现在不应擅自启动所谓“已获批触觉训练”或发布模型提升**。

## 我们如何自己建一条合格的训练样本

1. **定任务和真实种子**：在中继机只跑全新的独立回合，保存任务、实际seed、机器人和物体配置；未成功的规则专家样本与人为失手试片另入隔离负例，不能混在成功专家目录。
2. **同一次动作，同一物理时钟**：每个仿真物理步（当前约4 ms）记录四指接触代理；拍照时记录真实`physics_step`、三摄RGB、当前14维指令／关节状态。绝不用“视频25/50fps”倒算触觉时刻，也不拿另一回合即使同seed的触觉贴到图片上。
3. **只用过去、目标是下一专家动作**：以当前拍照步为锚点，从**之前25个物理步**构建5×4×3接触历史和5×4有效掩码；输入含当时三张图、当前14D状态和语言指令，监督标签是同回合**下一保存帧的专家14D指令**。未来接触／任务成败只能当离线评估或专门预定义目标，绝不进当前输入。
4. **验来源再编号**：规划、任务目标和same-run HDF5/raw/obs/frames完成门、relay单3090来源与SHA全部通过，才是候选成功示范；图像需真实可解码，拒缺帧、时间不前进、无效窗口、非数值、旧LXC来源。私有逐样本索引放Git忽略`data/reports/`；Git仓库只放小型计数／SHA卡，不放RGB、世界点或权重。
5. **按实际种子切分**：所有相同任务同seed的重试必须留在**同一**train/validation/test折，不能随机分帧；只从训练折拟合接触归一化并在验证／测试折固定使用。模型训练的视觉-only、正确触觉、时间打乱触觉应使用**完全相同的图像、状态、动作和种子折**。

现有[`build_relay_training_index.py`](<../src/build_relay_training_index.py>)对冻结的v1索引会CPU逐条重验原十份relay专家卡与HDF5、实际解码每对三路RGB、构造私有候选索引与脱敏SHA计数卡；明确选用`--bottle-v2`后又重验全部12份专家回合，CPU实际解码4083张三路相机画面、另建1361对的私有v2候选逐样本索引（train899/val230/test232），旧v1全部1112行和验证／测试折**完全未变**，只有双瓶两新seed追加249条训练候选；见[完整v2来源与分折报告](<RELAY_PAIRED_INDEX_V2_CANDIDATE.md>)。**索引不是已批准的训练集**，不会转换负例或视觉策略自回放为专家标签。优先补采更多**不同起始位置／物体／遮挡／接触前后／失手**的实际独立种子，再评审是否把候选数据、种子划分和归一化升级为可训练；五种子每任务只是建立技术切分，不支持显著性或泛化结论。尤其**接触帧多≠首次碰到物体的独立事件多**：在双瓶训练折341对中左右手各只有3个“此前未接触→下一帧首次接触”区间（每seed各1），而未来区间维持接触的重复帧分别有180／178对，详见[双瓶接触起点诊断](<BOTTLE_EXPERT_ONSET_LIMIT.md>)。若目标是预测接触起点，需补足**独立接触事件**而不是单纯增采相邻帧。[七种子候选v2方案](<RELAY_BOTTLE_SEVEN_SEED_CANDIDATE.md>)进一步说明：训练折从3增到5seed后，原全分箱力中位数8/8从正值变零，提醒我们**归一化必须随着新训练折重拟，绝不能继承旧统计或用验证/测试去调参数**；更新后的v2训练折虽有590对，首次接触也只增至左5/右6个区间，仍不支持可信接触起点预测头；这仍不是模型训练。

## 在线 RL 能不能做？

**理论上能，在仿真里有条件地做；眼下不建议直接对完整 LingBot-VLA 上线 RL。**离线模仿学习是读固定的 `(当时观察, 专家随后动作)`，在线强化学习则让当前策略真正控制仿真回合，观察成败/碰撞，再用回合奖励修改策略。两者不能把视频看起来像成功或单次选中seed的1/1说成总体成功率。

- **阶段一：离线起点。**固定原视觉权重，以已批准的同源训练折只训练小触觉adapter或LoRA；同数据视觉-only基线和接触窗口分层验证先过门。不把未来力泄进输入，不把自回放动作当专家纠错。
- **阶段二：仿真在线试点。**只对明确限定的任务／种子训练一个小型残差策略；策略逐次产生动作，真实完成整回合。奖励以**任务目标与可验证的阶段结果**为主；将碰撞、掉落和超时分别记录，防“刷触点数/冲量尖峰”骗奖励。训练种子与独立验证／测试种子永久隔离，统计全部尝试次数（包括失败和初始化异常），预先定义与视觉-only在同seed的对照。尤其原双瓶`check_success()`只按两瓶位置/高度判定，规则专家还允许夹爪保持闭合；RL若只刷这个终止奖励，可能学到“握着瓶子站在目标附近”，要把官方任务分数和额外放开夹爪后稳定性诊断分开报告，详见[在线RL奖励欺骗风险](<ONLINE_RL_REWARD_RISK_ZH.md>)。
- **资源门槛。**单张24GB RTX3090曾能BF16加载视觉基座推理，但完整VLA在线RL往往还需优化器状态、价值模型、多回合仿真/回放缓冲；目前**没有证据**它能在此机一边跑全部组件一边稳定更新。应先测显存峰值、推理和反向传播耗时，冻结基座、串行采样／训练并每段遵守GPU租约；不足则降级为更小可训练模块，而不是抢占Strata或假装已有RL结果。
- **实物机器人不进入当前路线。**SAPIEN `|impulse|/dt`只是假设性接触代理，不是经标定的夹持法向力或硬件限力。真实硬件在线探索需要传感器标定、关节与速度限位、急停、人类监督及独立安全审查，当前均未建立。

**决策：**先完成同源数据质量与接触覆盖补采、视觉-only/触觉离线基线，再用仿真小策略做可复现的在线RL可行性试点；当前无训练许可、无触觉模型或在线RL实验成绩。
