# 动作块执行来源干预 v1（开发机制实验）

## 问题与假设
前轮16场完成且原始数据独立复核通过。高频下低跟踪误差仍可能失败，因此先区分“每次重新预测只执行首动作”与“推进既有动作块”。不同时改动触觉适配器、观测状态或无接触残差。

## 固定比较
开发seed100145/100146、同一r0 step2880 true适配器；真实历史和历史置零两条件；执行来源fresh_first/cached_block两条件，共8场。两来源每个实际动作之前均重新采集当前观测、编码因果窗口、运行H50/10去噪推理，噪声沿用原有按已执行动作匹配规则。fresh_first执行当前预测第0项；cached_block每10动作保存当时完整预测，在这10动作中依次执行保存块的0–9项，其余当步预测仅记录、不得参与动作。缓存由已取得的历史观察生成，无未来数据。没有动作插值或ensemble。

这是闭环执行来源干预：缓存条件有意延迟新观察对控制的影响，并不单独证明触觉机制。它也不等同普通c10：仍保留每步观察和推理，须实测其额外调用是否改变仿真状态。两条件初始图像、状态、初始预测/动作及场景配对；分歧后不能要求噪声相同以外的观察相同。

## 门槛与记录
保持官方400动作、200000物理步、1200秒策略预算与1500秒外层预算；截断不可记任务失败或用于解释收益。首次技术异常停止，不自动重试；资源暂停仅在场次开始前恢复。仅自有GPU租约，原仓库/权重只读，不操作Strata。

现有PredictionTrace和validate_policy_rollout默认执行当前请求预测前缀，不能直接复用该假设来审批缓存条件。必须新增独立provenance记录并审计current_request_index、source_request_index、source_prediction_offset；每条实际指令必须精确等于已保存来源预测，且来源请求时刻不晚于执行时刻。HDF5请求仍归属于当前观察时刻；原始因果触觉及动作物理时钟审计保留。冻结前必须检验缓存边界、存储不别名、拒绝跳步和非有限输入，以及篡改来源/动作被拒绝。

## 预先约定的结果与下一步
报告全部8场原官方任务成功、截断/异常、接触对象、前60动作和首次桌面/瓶子接触后20完整动作实际qpos误差、完整来源追踪、耗时和图像。观察到缓存改善只支持执行调度值得进一步验证，不能视为独有触觉收益。两个开发seed不进行确认性显著性检验。

若所有条件仍失败，记录地板效应，转向独立无接触基础残差干预；不增加训练量以替代机制检查。若缓存改善，需先审计额外观察/推理对仿真状态无副作用，再制定新的独立seed确认协议；不得将已反复调试seed并入确认集。下一轮独立seed需先检查全仓数据和实验清单无使用记录，再冻结，不在开发结果后挑选易成功seed。
