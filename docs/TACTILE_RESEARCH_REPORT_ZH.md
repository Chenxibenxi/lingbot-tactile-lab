# LingBot 触觉研究阶段报告（面向非专门读者）

> **结论先行：**我们已经在本机单张 RTX 3090 上采到并核验了五条成功的机器人专家轨迹，建立了同回合图像、动作和接触记录的候选数据集，并把训练与评测所需的安全门禁、对照输入和评分规则写成可复测代码。但**还没有训练出触觉模型，更没有证明触觉提高了提锅成功率**。归一化、数据切分仍标记为未批准；原始图像、轨迹和模型权重不应上传 GitHub。

## 一、目标与我刚做了什么

研究问题是：在原有 LingBot-VLA **看图执行动作**的基础上，加入夹爪接触历史，是否真的有助于操作？为了不把不同回合的图像与接触记录误拼在一起，我们在独立的中继机工作区开发采集器：每个物理仿真步记录四根手指的接触代理量；相机拍照时记录真实物理步编号、两臂状态与指令；任务专家必须通过规划和目标成功检查，且原始数据、相机图像和完成标记的哈希一致，才允许产生候选数据卡。早先的 LXC 试验只用来验证工具，**不进入本机数据集**；规划失败或视频转换中断的回合也被隔离。

目前成功获得五个**实际种子互异**的 `lift_pot` 专家回合：合计 559 帧同源 HDF5 图像；去掉触觉历史不完整、前后帧没有正物理时间间隔的片段后，剩 518 个可用的「当前观测 → 下一帧专家指令」候选对。按照实际种子、而不是按随机帧，拟定训练 3 种子／309 对，验证 1 种子／104 对，测试 1 种子／105 对。详情与来源卡见[五种子试点](<RELAY_FIVE_SEED_PILOT.md>)及[候选切分](<../datasets/relay_lift_pot_seed_split_candidate_v1.json>)。五个种子达到**建立试验切分的技术下限**，但这些种子原先经过专家成功预筛、只有一个任务，不能据此估计一般场景成功率。

此前还对本机现存视觉权重做过一次**挑选种子的视觉-only闭环正控**：`154800` 权重在 seed `100048` 提锅成功一次，但那次模型并未读取触觉，不能拿 1/1 当总体成功率，也不能把视觉策略自己生成的动作冒充专家监督。它与上述重新采集的五条规则专家数据是**不同回合、不同来源角色**，详见[视觉基座回放记录](<STORAGE_AND_CHECKPOINT_REPLAY.md>)。

之后我检查了触觉输入是否真的有信息：训练折每根手指完整的历史分箱中，仅约 22.5%–23.0% 有非零接触。直接对全部分箱求中位数与四分位距会得到零中心、零间距，导致归一化比例全部落到人为设置的 0.1 下限；贸然训练可能放大少量接触值。于是增加**只用训练折正接触分箱**拟合的 v2 候选方案：无接触力始终映射为零，接触比例保持原值，归一化后力分量限定在 ±4。即便如此，正接触力的八个通道仍全部碰到 0.1 间距下限，表明信号可能接近常数；训练折约 4.76% 的正接触分量会被裁剪。它只是待评审的方案，代码会拒绝把这份未批准参数装进训练模型。见[归一化试点](<CONTACT_NORM_PILOT.md>)。

我还把全部 518 对真实三摄图像在 CPU 上解码，逐对构造三种**同图像、同当前状态、同下一动作标签**的输入：只看图像、看图像与真实触觉、看图像与「仅重排已经观察到的过去接触历史」。重排绝不借用未来力。但只有 123 对的当前历史出现非零接触；另外 **395 对**在重排前后触觉几乎没有区别。因此将来若只报告全体 518 对的平均动作误差，即使略有改善，也不能说改善来自触觉；必须单独报告接触期间的指标。见[同数据消融审计](<MATCHED_ABLATION_INPUT_AUDIT.md>)。

最后，我预先固定了[接触分层评测协议](<CONTACT_STRATIFIED_EVAL_PLAN.md>)：将来只有同时拿到三种方法对每一对数据的 **518×3＝1,554 条**真实模型动作预测，且模型／视觉基座／数据切分来源可核验，才计算每个独立种子的平均动作误差，并区分「当前已经接触」与「当前尚未接触」。用空预测做的实测会被拒绝（0/1,554），目前**没有模型评测数字**。考虑到训练折仅73/309对存在当前接触，又新增了只读取训练折的**候选损失权重**：逐独立种子平衡接触与未接触对，当前接触窗口约权重2.06–2.15，未接触约0.65–0.66；平均权重保持1，不修改验证／测试数据。它只是可能增加少数接触样本注意力的实验方案，也可能导致过拟合，因此仍标记为未批准、尚未用于训练。参数见[候选接触权重](<../configs/relay_lift_pot_contact_weights_candidate_v1.json>)。再只检查训练折的**标签与时间间隔**：309对里283对相隔15个仿真物理步（约60毫秒），其余26对是1–14步，不能简单套用「视频50帧/秒」假设；有既往接触的73对，其当前指令到下一帧专家指令的14维平均绝对变化约0.00535，无既往接触的236对约0.01352。差异只是混合关节/夹爪量纲的描述，**不说明触觉没用**；抓稳时本来可能无需大幅改指令，但也提示只靠下一帧动作模仿很难检测接触的作用。验证／测试折的动作标签没有用于这个训练方案诊断。见[训练标签与时钟诊断](<TRAIN_LABEL_TIMING_DIAGNOSTIC.md>)。

为检验「让模型预测下一帧是否第一次碰到锅」的辅助目标是否足够，另只在**训练折**用同回合真实物理步记录统计未来帧间首次接触：三种子309对里左手、右手各只有**3个首次接触正例**，并且双手发生在同一帧间区间。虽然左右各有76个「未来区间存在接触」样本，大多属于已经抓住后继续接触，不能把每一帧都当独立成功。因此现在**不应直接训练所谓接触预判头**；需先补更多位置、失手与临近接触反例。未来接触仅用于离线诊断标签，不进当前输入。见[专家接触起点负结果](<EXPERT_CONTACT_ONSET_NEGATIVE.md>)。全套 CPU 回归测试应以最新本地执行结果为准，这些测试验证的是代码契约，并非模型效果。

## 二、为什么选这些实验方法

1. **同回合、真实物理时钟，而不是按视频帧率硬拼。**相机拍照和接触采样频率不同；把另一次相同任务、相同种子的触觉轨迹贴到图片上，也不等于同一次动作。一个仿真物理步约 4 毫秒；以当前观测为终点，仅聚合此前 25 步（约 100 毫秒），分成五个时间箱，并附上有效性掩码。触觉历史覆盖约100毫秒，但相邻保存图像多为15个物理步、约60毫秒且并非完全等间隔；必须逐对读真实步号。这样推理输入只包含当时已经发生的接触，不会「偷看」动作执行后的力。
2. **按独立种子分组，而不是随机拆帧。**同一回合相邻图像和动作高度相似；随机分帧会把几乎一样的画面同时放进训练和测试，造成虚假的高分。相同实际种子的重试也不允许跨训练／测试折；归一化参数只能由训练折计算。
3. **同数据对照，先区分视觉与触觉的贡献。**只看图像是必须击败的基线；在同一图像、状态和标签上改变触觉输入，才可能辨别新增信息的价值。重排历史只作为破坏时间／手指对应关系的弱负对照，而且这批数据大多没有接触，不能单靠它判断模型有无进步。
4. **先锁验收门，再谈训练收益。**每条成功轨迹有成功检查和 SHA-256；候选切分与归一化都保留 `candidate`／`training_approval=false`，防止把「代码跑通」误报为「模型获批」。后续还需要更多不同位置、遮挡、失败及空夹等反例，再进行匹配数据的视觉-only 和触觉模型训练、真实闭环任务评测。
5. **不抢占 GPU、保留原始基线。**采样仅在服务无请求且取得 GPU 租约后临时卸载空闲模型，完成后恢复；最近的归一化与消融审计均只用 CPU。原始 RoboTwin 和历史视觉权重不写回，原始数据与新权重只放本机被 Git 忽略的目录。
6. **候选训练权重只针对「当时已观察到接触」。**不按未来是否会抓到东西、也不偷看测试折分配权重；先让三个独立训练种子贡献相近，再让每个种子的已接触／未接触类贡献相近。用分层测试检验是否有效，而不是靠重复稀有帧把数字抬高；尚未获准实际拟合模型。

## 三、常见术语速览

| 术语 | 在本项目中的准确含义 |
|---|---|
| **LingBot-VLA** | 把语言、视觉等观测映射为机器人动作的基座策略；目前真实运行过的基座仍是视觉策略，**不是已接入触觉的正式服务**。 |
| **RoboTwin／SAPIEN** | 机器人任务环境／底层物理仿真。我们从仿真接触点读「冲量÷物理步时长」作为接触负载**代理量**；它不是经标定的真实夹持力，不得用作硬件限力。 |
| **GelSight** | 能拍摄接触表面形变的实体触觉传感器；我们没有这种图像传感器，不能把仿真接触数值称作 GelSight。 |
| **同源 HDF5／因果时间窗** | HDF5 是存储同一专家回合三路相机图像与动作的容器；因果时间窗只汇总拍照时刻以前已观测的四指接触。 |
| **实际种子（seed）** | 决定该次仿真初始场景的随机数。不同 seed 有助于降低同一轨迹泄漏，但五个筛过成功的 seed 并非充分的统计样本。 |
| **14D 动作** | 左右手臂各六个关节指令加一个夹爪指令，共十四维。这里只用实际专家下一帧指令作离线标签，不把未来接触塞进模型输入。 |
| **掩码（mask）** | 标明时间箱／手指数据是否有效；缺测或过期不能默默假装为有效的零力。 |
| **中位数、IQR、log1p、裁剪** | 分别是稳健的中心值、上／下四分位之差、`log(1+x)` 压缩大数值、以及限制归一化输出幅度。这些都是数值处理选择，**不是物理单位校准**。 |
| **Adapter／消融／MAE** | Adapter 是尝试接在原模型状态表示上的小模块，当前仅有接口与 CPU 合约；消融是在其他数据不变时改变一项输入；MAE 是动作指令的平均绝对误差，**不等于提锅任务成功率**。 |
| **SHA-256／数据卡／GPU 租约** | SHA-256 校验文件是否被替换；数据卡记录来源与状态而不包含原始轨迹；GPU 租约用于避免与其他占用任务冲突。 |
