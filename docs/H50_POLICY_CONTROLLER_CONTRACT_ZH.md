# 用户选原H50控制语义后的首个真实门禁：专家旧轨迹**零条**`take_action`，不能由逐步drive-target凑50条

用户选择[保留原H50 `take_action`语义](<VLA_ACTION_CLOCK_DECISION_ZH.md>)，不是改成H16固定物理tick。原VLA客户端逐条调用[`TASK_ENV.take_action(act)`](</mnt/relaydata/lingbot/RoboTwin/script/eval_policy_client_lingbotvla.py.orig#L385-L403>)；原高层函数内部[TOPP规划并以可变物理步执行](</mnt/relaydata/lingbot/RoboTwin/envs/_base_task.py#L1479-L1665>)。相反，规则专家`move`针对双臂一起运动调用[`together_move_to_pose`](</mnt/relaydata/lingbot/RoboTwin/envs/_base_task.py#L794-L882>)或[`take_dense_action`](</mnt/relaydata/lingbot/RoboTwin/envs/_base_task.py#L1407-L1477>)。已验证的本机成功seed100013**同回合技术侧录**虽有**1,582连续物理步和120保存帧**，但按原raw/frames/commands同源校验后的`action_index`只有**6种规划阶段**、`expert_together`1282步＋`expert_dense`300步，真实`take_action`**调用0次**。这些不是可训练H50的6个/1582个高层标签；该同seed复演也绝不扩增独立seed。

新[仅CPU未来数据门](<../src/policy_highlevel_chunks.py>)要求调用者**先独立验真**专家成功completion/HDF5/相机/触觉来源SHA；它自身再只接受同trial/已核completion SHA及原`_base_task.py`源码指纹的**真正`Base_Task.take_action`**调用记录、各自14D命令和`(before_physics_step,after_physics_step]`连续且可变时长的执行区间；观测anchor必须在首个动作调用前拍摄，过去触觉最新步不能晚于相机捕获、捕获步号至少25，完整25步历史还须由上游同回合窗口校验器证明，SHA绑定当次RGB/HDF5，**只读train或validation，绝不拿test来选H50**。其后连续50个实际调用才生成未获批候选，绝不插值、重复、按固定5/15/50tick取样或把视觉策略自回放冒充规则专家。4项[合成负控](<../tests/test_policy_highlevel_chunks.py>)覆盖17/86/181可变跨度及跨动作断点、未来触觉、错源哈希、规则专家逐step/策略自回放、短于50条、test折拒绝。**这只是验收条件，不是本机已有合格H50示范。**

下一步必须先在独立、可回退的专家实验分支**设计并证明**能把规则专家规划输出转换成受控的高层14D `take_action`调用序列（不使用它自身的未来接触/图像作输入），逐次记录源观测/物理区间/14D动作与原成功门SHA，再在一条已知物理seed上只作技术pilot，检查是否规划/目标成功且连续动作≥50；失败如实登记，不补旧轨迹或宣称已找到监督。仅技术pilot成功也不算新独立seed，需更多不同seed的train/validation、未来专家来源逐件SHA门、训练折动作/触觉归一化评审，负责人另行明确批准。现有注册表`approved_paired_episodes=[]`和六份candidate norm均`training_approval=false`，不运行VLA训练forward/optimizer、不启用真实RPC能力或声称触觉收益。Strata继续由systemd active+enabled托管，GPU本轮未动。
