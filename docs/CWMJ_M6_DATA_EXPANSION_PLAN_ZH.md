# M6 数据扩展与独立确认计划（下一阶段，尚未运行）

## 为什么继续

M4仅2个训练seed、1个验证seed。单次闭环成功与训练权重的零力响应混杂；M5解决输入依赖问题，但仍重用测试seed。无论M5正负，都不足以评估稳定泛化。下一步优先扩大独立同源数据，保留所有失败，不通过不断重试筛选有利场景。

## 首个短期任务：固定采集

待M4/M5闭环及图文报告完成、确认自有GPU空闲后，固定train100055–100066（12个）、validation100067–100070（4个）各尝试一次。当前CPU检查这些seed在data/paired全部任务目录无历史占用；每次运行前仍需原fresh-seed门验证，不因本检查绕过。100071–100086预留独立确认，采集器不使用；M4/M5的51–54仅作为已有探索性测试记录，不再视为新确认样本。

沿用CWMJ v2资产manifest/factory、源专家、stride20、128请求/10000物理步/900秒限制、原稳定门和成功判据。无调整质量门、资产或采样规则，失败不补seed。这里只做原专家可完成的正常抓取覆盖扩展，不冒称已具备扰动恢复数据。

## 数据门与下一阶段

新增至少4个通过完整来源校验的训练seed、2个验证seed，各至少4个接触及4个非接触有效窗口；原训练45/46可在新manifest显式合并，原验证49永不入训练。若不达门，停止本阶段拟合并报告初始化/规划/接触覆盖瓶颈。接触数阈值属于数据可用性，不按模型效果筛seed。

通过后才冻结训练预算、3个训练随机初始化及独立确认评估方案；至少zero/true/mismatch同容量同数据同预算，必要时保留mean对照，但不能用均值控制排除非线性分布混杂。选择最后固定训练步权重，不能按新验证效果挑模型。验证、测试按seed汇总，不能把窗口当独立样本。确认必须包含成功率、同权重输入干预与不一致配对，报告所有初始化拒绝/截断及多重比较边界。

## 长期任务

1. 构建失败阶段诊断，增加可追溯瓶功能点轨迹，区分未接触、抓取失败、抬升失败、放置失败；观测记录不能改变控制。
2. 在单独协议中实现受控扰动与可验证的专家恢复，生成同源因果触觉/观测/动作。失败rollout不得直接作为专家标签。
3. 检验更短反馈间隔、历史窗口及传感器消融；每次只改预声明因素，并承担动作频率变化的公平对照。
4. 在多资产和原20瓶场景独立验证，明确替换资产的分布边界。不能由单一酒瓶场景外推原比赛成绩。

每个采集、训练、闭环实验即时完整图文汇报。原仓库/checkpoint只读；自有GPU租约串行，遇其他负载停在CPU工作，不重启Strata。阶段是否继续由数据质量与证据决定，不以获得正结果为目标。
