# 双瓶任务在线 RL 奖励设计：先防“刷成功”

**只读原RoboTwin检查**：[`pick_diverse_bottles.py`](</mnt/relaydata/lingbot/RoboTwin/envs/pick_diverse_bottles.py>) 的 `check_success()`仅要求两瓶functional point分别在固定目标的XY各±0.1范围且z>0.89；规则专家`place_actor`的两臂调用都传`is_open=False`。这就是**当前原任务成功判据**，我们不改原RoboTwin或伪称它检查“已松爪并稳定落座”。如以后把它直接当在线RL唯一稀疏奖励，策略可能学到“握着瓶子停在目标附近”就得分，而不一定能稳妥完成更严格的物理放置；不能把一个优化后的数值误报为真实机器人完成率。

## 建议的仿真实验分两套明示指标

1. **原任务兼容指标（不更改基线）：**每次尝试完整记录真实 `check_success()`、超时、初始化失败/规划失败（若存在）、随机实际seed及策略动作；与视觉-only在相同seed、相同运行时限比较。不要预筛成功种子后只报1/1。
2. **附加的研究稳定性诊断（不是RoboTwin官方成绩）：**在独立沙盒单独记录瓶是否曾到目标、两手是否仍抓持/接触、无动作观察窗内是否保持位置、是否跌落/异常碰撞；事先约定观察窗和容差，别事后换阈值挑高分。若设计松爪/放置要求，须明确是**新研究任务**，不把其数值与旧 `check_success()` 混成一项。世界瓶子位姿可作**训练奖励/事后诊断的特权信息**，不得混进在线策略的当前RGB/状态/过去触觉输入。
3. **触觉只作因果观测，不拿大冲量奖惩碰撞：**四指原始`|impulse|/dt`是未标定代理，不是正常夹紧力、滑移真值或硬件阈值；单纯奖励“接触点多/力大”会鼓励穿模或猛撞。异常值按预先设定的诊断门标注，真实硬件安全另需标定与独立限力。

**顺序：**候选数据训练批准→同数据离线视觉-only/触觉小adapter与接触分层对照→量测单RTX3090模型/仿真/优化器峰值和单回合时间→固定训练／验证／测试实际seed的仿真小策略在线RL试片→最后谈是否值得扩规模。当前无经批准训练适配器、无在线RL回合或RL成绩；在线RL无法靠已有两条人为开爪失败轨迹代替策略自己互动获得的回合数据。真实机器人在线RL当前不在计划内。
