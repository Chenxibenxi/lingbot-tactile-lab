- Target: `lift_pot`, `demo_clean`, known-positive starting/actual seed `100048`, local relay RTX 3090, original complete 154800 FP32 checkpoint loaded as BF16. Same seed in earlier passive pilot also succeeded, but outcomes can vary; this run alone cannot estimate success rate.
- Isolation: copied RoboTwin tree + probe-instrumented private overlay under ignored `work/`, opt-in generated eval-client copy and guarded launcher (no source curobo YAML/.pth writes). The running model **never received tactile**; it remained visual-only. Before GPU use Strata had no active/queued requests, the GPU lease was acquired; after evaluation Strata reported `loaded=true` and lease was released.
- Outcome: policy reported **1/1 success**, 100 actions actually executed. Two model-infer attempt markers, at actual physics steps 0 and 5,499; initial force window invalid, second 25-step window causal and valid. Request-aligned HDF5 stores actual three-camera RGB input, 14D state and tactile window; actions are recorded only after each real `take_action` call with before/after physics steps. This trial's private raw/camera/request/HDF5 artifacts occupy about 9.4 MB under `data/eval/154800-policy-capture-seed100048-v1/`.
- Independent `src/validate_policy_rollout.py` CPU audit checks source identities, marker clocks and exact request-boundary RGB geometry, online-vs-offline tactile window equality, each actually applied 14D command's request membership and monotone physics interval. **Passed:** 2 request images, 100 applied commands, 1 valid causal tactile request, self-rollout success flag 1. Byte counts/SHA256 and the model index checksum are in `datasets/relay_policy_self_rollout_154800_s100048_v1.json`; private bytes remain gitignored.
- Scientific limit: successful *visual model self-rollout* is **not** an expert demonstration or a tactile-conditioned model. The 100 actions are generated by the visual model itself, not corrective force supervision, and images exist only at 2 inference requests rather than at each action. This card is explicitly `training_approved=false` and is **not** included in `datasets/provenance_v1.json:approved_paired_episodes`; no tactile training or improvement claim follows.
- Contact target feasibility check (CPU, no new GPU use): first left/right contact in this success occurred at physical steps 6,809/7,398, respectively **1,310/1,899 steps after the second inference request** at step 5,499. Therefore a naive 25-step (~100 ms) future-onset label would be negative even for this successful trial and is unsuitable as the only training target for this slow, action-chunked policy. `src/contact_targets.py` instead computes *future targets only* over each **actually executed action's** `(before, after]` physics interval after validating the same-run four source files. Among 100 actions, 33 left and 28 right action intervals contained contact. The 52 KB private labels remain under ignored `data/reports/`, never joined into current infer inputs. This is weak simulation contact supervision, not calibrated grip force or expert corrective actions; a single selected seed supplies no valid held-out split.
- Next gate: record additional independent seeds and controlled failure/occlusion cases, validate action/image coverage and independently fit normalization on training seeds, choose an honest training/control design.
