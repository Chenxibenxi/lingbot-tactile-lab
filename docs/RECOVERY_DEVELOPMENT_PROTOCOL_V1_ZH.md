# 固定开爪后的恢复示范：开发协议 v1

目的：验证当前场景规则专家能否在一次明确开爪干预后完成原任务，并形成不泄漏干预标签的同源候选数据。本实验是采集可行性开发，不评估VLA、不证明触觉因果收益，不改动正在运行的M8。

## 预先固定的矩阵

开发seed为100119、100120、100121、100122，每个seed两条件：无扰动专家、固定左爪打开后一次恢复，共8回合。顺序为seed升序、无扰动先行。已检查原始paired/eval目录和数据登记，未发现使用；单独登记为development，禁止成为未来独立确认集。不补选seed，不因失败重复同回合。

使用原CWMJ v2资产、相同原始初始化和任务成功判据，原控制器take_action(qpos)。专家规划采样stride固定20。最多400次动作、60000物理步、1200秒；单次原控制器调用若越过物理上限，记录超限并停止，不再执行后续动作。每次尝试以独立进程和自有租约运行。训练/评测GPU队列优先，此开发试验目前只登记、不自动抢占或并发运行。

## 干预与恢复

在首次lift阶段所有提案执行完毕、第一个place提案执行前，用当前实测14维状态保持双臂及右爪，仅将左爪命令设为1.0，并通过原take_action执行一次。干预动作前先capture真实RGB和物理时钟。此动作source_role必须为external_intervention，不是专家标签。

废弃原place提案；从干预后的当前场景重新规划grasp/lift/place，只允许这一轮恢复，不二次干预、不无限重抓。恢复动作source_role为expert，但仍未批准训练。无扰动条件不插入额外动作、不重新规划。触发前若已完成任务、规划失败或触达预算，记录干预未发生，不能报告成功恢复。原check_success与eval_success共同决定终态，不以图像或Strata描述判定成功。

## 保存与审计

逐动作保存命令、角色、阶段、相机索引、capture/before/after物理步及段号；原力代理量、相机、HDF5均来自同一运行。角色、干预时刻、几何真值、阶段、最终结果只作专家或审计信息，不进入学习者输入。两条件初始RGB/状态/资产需一致；干预前匹配动作序列，之后不要求一致。

先运行恢复时钟审计，再用validate_expert_data与完成清单核验真实HDF5、图像和源SHA。仅在原任务成功、干预实际发生、恢复成功且所有数据审计通过时记为“可用恢复候选”。失败与规划异常仅诊断。H50标签不跨越干预、不重复尾部；不足50的真实尾部由掩码处理，而非伪造未来动作。此开发集即使通过仍不自动进入正式训练，后续训练/验证需独立冻结来源清单。

## 可行性判据与报告

每回合保存完整图文，包括相机阶段、抓手命令/触觉代理量、扰动动作、终态、审计、失败原因、局限与复现。最终固定报告4对结果，不做显著性检验。开发门为：至少3/4无扰动官方成功；至少2/4扰动条件实际触发且官方成功、预算未超限并通过数据审计；全部有效对初始状态与干预前动作一致。任一基础设施未知/中断仍保留原分母并单列未知，开发门不通过，不冒充完整失败。

通过仅表示值得另立规模化恢复采集协议，不代表稳定恢复率或触觉模型收益。未通过则依据固定8回合定位几何/规划/接触/控制或数据问题，后续修订使用新协议和新seed。GPU执行前还需完成记录器、报告器及测试，并冻结源码/资产清单；不能只凭本协议或CPU测试宣称实验已运行。
