# 双瓶动作密度“25改20”的CPU研究方案：只改规划路径索引，不补旧回合

用户已核准**仅CPU设计**，没有批准另一个新seed试采或任何GPU任务。[真实seed100022的试采](<H50_ONLINE_EXPERT_S100022_RESULT_ZH.md>)在46条原`take_action`后提前任务成功，离H50要求50条少4；该seed已用，旧数据不得更名/重跑、不能成功后多挥手4次凑监督。现有[`online_expert_proposals`](<../src/online_bottle_expert_actions.py>)默认仍固定**每25个新规划路径索引**抽取一个双臂目标，`record_online_expert_demo.py`/执行适配器继续只用这个原默认；新参数`stride=20`只是一个**显式传入的实验候选**，错误19、布尔True等输入直接拒，绝不默默改既有试验结果。

原理用大白话说：一条规划路线是一串路标，原来每25个路标发一次高层指令；新想法在下一次**新的场景**中每20个路标发一次，接近同样的目标但指令可能更密。它可能增加在原任务到达成功门**之前**发出的真实`take_action`条数，却不能保证达到50：短路径、阶段中途成功、TOPP耗时变长、双臂跟踪/碰撞改变都可能反向影响结果。**20/25是规划路径数组索引，不是20/25个物理时钟步，也不是5Hz/10Hz**。原夹爪闭合仍严格只有1条，不能人为重复无位移动作作假。

[CPU脱敏候选卡](<../datasets/online_bottle_stride20_cpu_candidate_v1.json>)仅在一个**人造**长度26的双臂路径假场景验证：原默认25抽到抓3/抬1/送2共6条，新显式20为抓5/抬2/送4共11条，夹爪命令始终1条。这**不等于**真seed100022会从46变成多少条，更不能得出新seed胜率、H50合格或力安全。已知seed100022成功所见46只用于产生假设，绝不偷偷挑同seed重播进行模型/参数选择。候选json明确`predicted_new_seed_h50_calls=null`、`eligible_h50_windows_verified=0`、`training_approval=false`。

要开展下一轮真实研究，必须由负责人**另行**批准新独立seed、固定物理步/墙钟预算和一次性输出ID；其训练/验证/test种子不得与原fold或100022混用。提前固定stride20，不根据新回合头几条接触/图像/目标距离动态调参；阶段内只允许从**该回合当前**机器人和瓶位规划几何路径，图片与过去触觉在实际动作前拍，执行后的结果不能倒灌。任务成功还要真动作≥50、同回合照片/触觉/实际控制区间及成功HDF5 SHA全验，由负责人**再**审批数据与训练归一化；单新seed即使同时成功且≥50，也不够独立的训练+验证两折。与旧seed25的结果跨seed比较只是一种探索性观察，**不能把stride效应同场景seed效应分离**。本文系**试前CPU假设快照**：后来用户另行批准唯一新seed100023/10,000步/900秒真实stride20试采，结果见[独立新seed H50来源报告](<H50_ONLINE_EXPERT_STRIDE20_S100023_RESULT_ZH.md>)；不因此反推本CPU人造计数证明stride单独有效，仍不启动VLA训练/正式RPC。
