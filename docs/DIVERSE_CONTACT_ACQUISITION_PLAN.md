## Bounded second-task pilot

The existing local RoboTwin source's `pick_diverse_bottles` task samples two bottle models (indices 0–19) at varying left/right positions, asks the corresponding arms to grasp, lift, and place both bottles, and checks their final poses. This introduces different contact geometry from a single shared pot. A historic *local evaluation* log records selected seed `100000` as a visual-policy success and seed `100007` as a policy failure, but neither policy result proves what a **new rule-expert rollout** will do on the current relay setup. They are predeclared candidates, **not** cherry-picked proof or a mixed success-rate denominator.

`src/run_expert_relay.sh` and `src/record_expert_demo.py` allow only this added task alongside the original allowlist; original RoboTwin files stay read-only. Source inspection of Strata's `serve/server.py` confirmed that after finishing a request, `busy` becomes false but the last `phase=thinking` is **not cleared**. Therefore the earlier phase-only guard was over-conservative: acquire the GPU lease, require authoritative `busy=false` and integer `queued=0`, then use Strata's **FIFO-protected atomic `/v1/unload`** (it returns busy if a new request races in), before stopping only its unloaded service. The corrected versioned `src/strata_idle_gate.py` refuses actual busy/queued requests and does not mistake a stale phase label for a live task.

The owner explicitly requested Strata stopped until **2026-11-02 12:00 Asia/Shanghai**, and an automatic restoration reminder was scheduled before stopping. All five preregistered seeds 100000/100007/100002/100009/100012 have since succeeded as **rule experts** under bounded GPU leases while Strata stayed stopped; aggregate counts, 3/1/1 pilot split and train-only preprocessing are in [the five-seed bottle report](RELAY_BOTTLE_FIVE_SEED_PILOT.md). This is not a population success rate: seed100007's historic *visual policy* failure does not turn its successful new rule-expert rollout into a failure example.

For a separate **single, natural-failure diagnostic**, preregister seed **100001** on the same task with new trial ID `relay_pickdiverse_s100001_expert0` and a strict 660-second cap. That seed did not appear among the historic evaluation's completed seed list, but this alone does **not** prove an expert failure or specify a failure phase. If the new rule expert fails, retain its failure.json and contact traces as a **rejected diagnostic**, never an expert training card; if it unexpectedly succeeds, retain the new trial separately and do **not** change the frozen five-seed split without explicit re-review. No same-seed retries or fallback hosts. Recheck lease/GPU ownership each time; do not restart Strata before the owner-approved deadline or let a scheduled restoration interrupt an active lease.

An expert success can produce a task-specific **unassigned candidate card** only after planner and task goal pass, same-run HDF5/frame/physics observations and hash-bound success/completion gates validate. A planner/task failure is a **separate negative diagnostic**: retain its rejected `failure.json` and telemetry locally, never call it an expert positive, do not force a `completion.json`, do not put it in train/validation/test, and do not treat missing HDF5 as a successful visual negative. The existing planner-failure lift-pot trials remain private diagnostics. Five accepted bottle seeds permit only an **unapproved technical pilot** split; the one-off failure diagnostic does not enter either task's expert train/validation/test set or alter either frozen split.

## What would make a useful counterexample

Record source roles and seeds independently; count observed left/right finger contact, missing telemetry, first contact and failed/no-contact paths. To test anticipation, acquire controlled near-contact misses and visually similar successes with different outcomes, *without* injecting future object state or force into inputs. Future force is permitted only as an offline target and only after a real executed action interval. A task/task-family split and more varied seeds are required before generalization claims. SAPIEN impulse/dt remains an uncalibrated proxy, not a GelSight observation or a hardware gripper force bound.
